What changed

Goal: a scriptable surface over the exact pipeline the Tauri app uses, so the agent loop is testable and other agents can drive it — without the UI.

1 · Behavior-preserving refactor no app behavior change

The Tauri-free core of generate_carousel_pdf was extracted from commands.rs into a new generation.rs (prepare_run / spawn_driver / finalize + run-dir naming + log tee). The Tauri command keeps only the in-memory process map + watcher (the UI-cancel concern) and calls the shared core. Run-dir naming and the crash-finalize safety net now live in exactly one place — required by the repo's error conventions. commands.rs: −294 / +64 lines.

2 · New happycampr-carousels-cli binary create · import · generate · status · open

A second [[bin]] in the same crate. Thin clap parser → pure, unit-tested handlers in cli.rs (incl. a deck-markdown parser that splits on # Slide … blocks). Headless: it supervises the bun driver, streams logs, opens the PDF. Reads/writes the same db.sqlite as the app (a CLI carousel shows up in the UI and vice-versa).

3 · The tauri build regression — caught & fixed

Why it mattered: a 2nd [[bin]] with no package.default-run makes tauri build fail with failed to find main binary. cargo test/check/build all stayed green (they build every bin), so a partial verification missed it. Fixed with default-run = "happycampr_carousels", then verified by a complete tauri build --debug that produced Happycampr Carousels.app + the dmg. Lesson recorded in STATUS.md.

Using the CLI

cd src-tauri
cargo run -q --bin happycampr-carousels-cli -- <cmd>        # or: cargo build --release --bin happycampr-carousels-cli

happycampr-carousels-cli carousel create --label "Launch" [--orientation vertical|landscape]
happycampr-carousels-cli carousel list
happycampr-carousels-cli slide add <id> --file s.md            # or --stdin / --content "…"  [--title T]
happycampr-carousels-cli import --new --file deck.md           # splits on `# Slide …` blocks
happycampr-carousels-cli import --carousel <id> --file deck.md # append to an existing carousel
happycampr-carousels-cli generate <id>                         # blocks, streams logs, opens the PDF
happycampr-carousels-cli status <id> [--log 40] [--watch]
happycampr-carousels-cli open <id>

Caveats to know (documented in STATUS.md)

  • Cross-process cancel is out of scope — the app's cancel uses an in-memory map. Ctrl-C on a blocking generate is the supported cancel; re-running self-heals a stuck state.
  • No --detach — it was built then removed (dead run.log + unsupervised). generate is always blocking + supervised; background it at the shell for async use.
  • Untrusted decks: slide text is fed to the design agent. Only import deck files you wrote/reviewed.
  • The real agent loop is intentionally not unit-tested (network/cost/minutes); its pieces are. Covered by the live E2E above.
